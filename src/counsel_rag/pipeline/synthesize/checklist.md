# synthesize 산출물 사람 검수 체크리스트 (G2)

`validate.py`는 형식·금칙(실명, reviewed 값, targets 값, sources 형식, 섹션 존재)만
기계로 거른다. 그 통과는 필요조건일 뿐 충분조건이 아니다 — 아래는 기계가 볼 수
없는, 사람만 판단할 수 있는 항목이다. 전부 확인 후 `reviewed: true`로 바꾼다.

## 1. 내용 정확성

- [ ] 원 소스(corpus/atomic)의 방법론·원칙이 왜곡 없이 재기술됐는가
- [ ] 소스 2개 이상을 종합했다면, 상충하는 조언이 있을 때 임의로 하나만 취하지
      않고 절충하거나 상황별로 구분했는가
- [ ] 소스가 1개뿐이라면 frontmatter에 note로 그 사실이 남아 있는가

## 2. 조각(섹션) 완결성

- [ ] 각 `##` 섹션을 그 섹션만 떼어 읽어도 "상황 → 원칙 → 구체적 방법"이 이해되는가
- [ ] "위에서 말했듯", "앞서 언급한 것처럼" 류 상호참조가 없는가
- [ ] 섹션 제목만 보고 내용을 추측할 수 있을 만큼 구체적인가 (예: "방법" 같은
      막연한 제목은 아닌가)

## 3. 실명·인용 흔적

- [ ] 채널명·전문가명·프로그램명이 본문 어디에도(주석 포함) 없는가
- [ ] 특정 전문가의 시그니처 이론명·고유 명명이 일반 언어로 풀렸는가
- [ ] 원문 문장을 그대로 옮긴 부분이 없는가 (표현이 원 소스와 우연히 같은 게
      아니라, 문장 구조·어순까지 베낀 흔적이 없는가)

## 4. 좁히는 질문의 실용성

- [ ] `## 상황을 좁히는 질문`의 각 질문이 실제로 이후 안내를 갈라주는가
      (답이 뭐든 같은 조언으로 이어지는 질문은 무용하다)
- [ ] 양육자가 스스로 답할 수 있는 질문인가 (전문 용어·모호한 기준 없이)
- [ ] 소스에 있던 구분법을 놓치지 않고 옮겼는가

## 5. 위기 연결(escalates_to) 적절성

- [ ] `edges`에 `escalates_to`가 있다면, 그 연결이 실제로 위험 신호를 가리키는가
      (과잉 연결로 모든 문서가 위기로 이어지지 않는가)
- [ ] 위기 신호가 소스에 있는데도 `edges`에 반영되지 않은 채 누락되지 않았는가
- [ ] 연결 대상 slug(`crisis-*`)가 실제로 존재하는 문서인가

## 6. 청자·화법

- [ ] 기본 청자(양육자) 화법을 지켰는가 — "아이가 ~할 때 (양육자가) 이렇게 한다"
- [ ] 당사자 본인 화법("나는 ~한다")이 섞여 있지 않은가

---

전부 통과하면 frontmatter의 `reviewed: false`를 `true`로 바꾸고 커밋한다.
